## 1. Протокол HTTP

**HTTP (HyperText Transfer Protocol)** — протокол прикладного уровня для передачи гипертекста (и вообще любых данных) между клиентом и сервером.

Основные свойства:

- работает по схеме **«клиент-сервер»** и обменивается сообщениями по схеме **«запрос-ответ»**: клиент (браузер) отправляет запрос, сервер (например, `httpd`/Apache) возвращает ответ;
- основной объект манипуляции — **ресурс**, на который указывает **URI**;
- **stateless** (не хранит состояние): каждый запрос обрабатывается независимо от предыдущих. Чтобы «помнить» пользователя (сессии, авторизация), используются **cookies**;
- может служить «транспортом» для других протоколов прикладного уровня;
- текстовый (в версиях 1.x): сообщения можно прочитать глазами.

### URI, URL, URN

| Термин | Что это | Пример |
|---|---|---|
| **URI** (Uniform Resource Identifier) | Любой идентификатор ресурса: `<схема>:<идентификатор>` | обобщает оба вида ниже |
| **URL** (Uniform Resource Locator) | URI, указывающий, **где** находится ресурс | `https://se.ifmo.ru/~s123456/index.html`, `mailto:joe@example.com` |
| **URN** (Uniform Resource Name) | URI, задающий **имя** ресурса без его местоположения | `urn:isbn:5170224575` |

Структура URL:

```
https://se.ifmo.ru:443/~s123456/lab1/index.html?x=1&y=2#result
└─┬─┘   └────┬────┘└┬┘└──────────┬────────────┘└───┬───┘└──┬─┘
схема       хост   порт        путь               запрос  фрагмент
```

### Структура запроса

Запрос состоит из трёх частей:

1. **Стартовая строка:** `Метод URI HTTP/Версия`
2. **Заголовки:** строки вида `Ключ: значение`, после них **пустая строка**
3. **Тело сообщения:** необязательно (у `GET` обычно нет, у `POST` есть)

```http
GET /~s123456/lab1/index.html HTTP/1.1
Host: se.ifmo.ru
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/130.0
Accept: text/html
Accept-Language: ru-RU,ru;q=0.9
Connection: keep-alive

```

Запрос с телом (отправка формы методом POST - обычно используется для приватных данных: паролей и тд):

```http
POST /check HTTP/1.1
Host: example.com
Content-Type: application/x-www-form-urlencoded
Content-Length: 11

x=1&y=2&r=3
```

### Структура ответа

1. **Стартовая строка:** `HTTP/Версия КодСостояния Пояснение`
2. **Заголовки**, затем пустая строка
3. **Тело:** HTML-страница, картинка, JSON и т. д.

```http
HTTP/1.1 200 OK
Date: Thu, 08 Oct 2026 18:00:00 GMT
Server: Apache
Content-Type: text/html; charset=utf-8
Content-Length: 4722
Last-Modified: Thu, 08 Oct 2026 17:56:00 GMT

<!DOCTYPE html>
<html lang="ru">...
```

### Методы запросов

| Метод | Назначение | Есть тело запроса | Безопасный* | Идемпотентный** |
|---|---|---|---|---|
| `GET` | Получить ресурс | нет | да | да |
| `HEAD` | То же, что `GET`, но ответ **без тела** (только заголовки) | нет | да | да |
| `POST` | Передать данные ресурсу (отправка формы, создание объекта) | да | нет | нет |
| `PUT` | Загрузить (заменить) содержимое по указанному URI | да | нет | да |
| `PATCH` | Частично изменить ресурс | да | нет | нет |
| `DELETE` | Удалить ресурс | обычно нет | нет | да |
| `OPTIONS` | Узнать возможности сервера / разрешённые методы | нет | да | да |
| `TRACE` | Вернуть запрос обратно (диагностика) | нет | да | да |
| `CONNECT` | Установить туннель (например, для HTTPS через прокси) | нет | нет | нет |

\* **Безопасный** — не изменяет состояние сервера.
\** **Идемпотентный** — повторный одинаковый запрос даёт тот же результат, что и первый.

**GET и POST — главное отличие.** В `GET` параметры передаются в URL (`?x=1&y=2`): они видны в адресной строке, сохраняются в истории и закладках, а длина URL ограничена. В `POST` данные идут в теле запроса: так можно передавать большие объёмы и файлы, и данные не видны в адресе.

### Коды ответов (состояния)

Код состоит из трёх цифр, **первая цифра задаёт класс**:

| Класс | Значение | Примеры |
|---|---|---|
| **1xx** | Informational — информационные | `100 Continue`, `101 Switching Protocols` (переход на WebSocket) |
| **2xx** | Success — успешно | `200 OK`, `201 Created`, `204 No Content` |
| **3xx** | Redirection — перенаправление | `301 Moved Permanently`, `302 Found`, `304 Not Modified` (взять из кэша), `307`/`308` |
| **4xx** | Client error — ошибка клиента | `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `405 Method Not Allowed` |
| **5xx** | Server error — ошибка сервера | `500 Internal Server Error`, `502 Bad Gateway`, `503 Service Unavailable`, `504 Gateway Timeout` |

### Заголовки

Формат: `Ключ: значение`. По лекции их делят на **4 группы**:

| Группа | Где используются | Примеры |
|---|---|---|
| **General Headers** (общие) | в любых сообщениях клиента и сервера | `Cache-Control`, `Connection`, `Date` |
| **Request Headers** (заголовки запроса) | только в запросах клиента | `Host`, `User-Agent`, `Accept`, `Accept-Language`, `Referer`, `Cookie`, `Authorization` |
| **Response Headers** (заголовки ответа) | только в ответах сервера | `Server`, `Location`, `Set-Cookie`, `Allow`, `WWW-Authenticate` |
| **Entity Headers** (заголовки сущности) | описывают тело сообщения | `Content-Type`, `Content-Length`, `Content-Language`, `Content-Encoding`, `Last-Modified` |

Самые важные:

- `Host` — имя сервера, обязателен в HTTP/1.1, так как на одном IP-адресе может быть много сайтов;
- `Content-Type` — тип данных в теле (`text/html; charset=utf-8`, `application/json`);
- `Set-Cookie` / `Cookie` — сервер ставит cookie, браузер потом присылает её в каждом запросе, так реализуются сессии;
- `Location` — куда перенаправить (вместе с кодами `3xx`).

### Версии HTTP (кратко)

- **HTTP/1.0:** одно соединение на один запрос.
- **HTTP/1.1:** постоянные соединения (`keep-alive`), обязательный `Host`.
- **HTTP/2:** бинарный формат и много запросов параллельно в одном соединении.
- **HTTP/3:** работает поверх QUIC (UDP).
- **HTTPS:** это HTTP поверх шифрования TLS.

## 2. Язык разметки HTML

**HTML (HyperText Markup Language)** — стандартный язык разметки документов в интернете. Браузер интерпретирует его и отображает в виде отформатированного документа.

Особенности:

- создан Тимом Бернерсом-Ли в 1989–1991 годах;
- исторически частный случай **SGML**; существует XML-нотация **XHTML** (строгие правила: все теги закрыты, нижний регистр);
- это язык **разметки**, а не программирования: он описывает **структуру и смысл** содержимого, а внешний вид задаёт CSS, поведение — JavaScript;
- текущая версия — **HTML5** (живой стандарт WHATWG). Она добавила семантические теги, новые типы полей форм, `<canvas>`, `<video>`, `<audio>`, LocalStorage и др.;
- HTML «прощающий»: браузер старается отобразить даже документ с ошибками.

### Элементы, теги, атрибуты

Документ состоит из **элементов**. Начало и конец элемента обозначаются **тегами**:

```html
<p>Это абзац</p>
```

- **Пустые (одиночные) теги** не имеют закрывающего тега: `<br>`, `<hr>`, `<img>`, `<input>`, `<meta>`, `<link>`.
- **Атрибуты** задают свойства элемента и пишутся в открывающем теге: `имя="значение"`.
- Элементы могут быть **вложенными**, причём закрываться в обратном порядке:

```html
<b>Этот текст полужирный, <i>а этот — ещё и курсивный</i></b>
```

### Основные теги

| Назначение | Теги |
|---|---|
| Структура документа | `<!DOCTYPE html>`, `<html>`, `<head>`, `<body>` |
| Служебные (в `<head>`) | `<title>`, `<meta>`, `<link>`, `<style>`, `<script>` |
| Заголовки | `<h1>` … `<h6>` |
| Текст | `<p>`, `<br>`, `<hr>`, `<strong>`, `<em>`, `<b>`, `<i>`, `<span>`, `<code>`, `<pre>`, `<blockquote>` |
| Ссылки и медиа | `<a>`, `<img>`, `<video>`, `<audio>`, `<canvas>` |
| Списки | `<ul>`, `<ol>`, `<li>`, `<dl>`, `<dt>`, `<dd>` |
| Таблицы | `<table>`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>` |
| Формы | `<form>`, `<input>`, `<label>`, `<select>`, `<option>`, `<textarea>`, `<button>`, `<fieldset>`, `<legend>` |
| Семантические блоки (HTML5) | `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`, `<footer>` |
| Нейтральные контейнеры | `<div>` (блочный), `<span>` (строчный) |

**Блочные и строчные элементы.** Блочные (`div`, `p`, `h1`, `section`, `table`) занимают всю ширину и начинаются с новой строки. Строчные (`span`, `a`, `strong`, `img`) идут в потоке текста.

### Основные атрибуты

**Глобальные** (есть у любого тега):

- `id` — уникальный идентификатор элемента на странице;
- `class` — один или несколько классов (для CSS и JS);
- `style` — встроенный (inline) стиль;
- `title` — всплывающая подсказка;
- `lang` — язык содержимого;
- `hidden` — скрыть элемент;
- `data-*` — пользовательские данные (`data-value="5"`, в JS доступно через `el.dataset.value`).

**Специфичные:**

- `href` у `<a>` и `<link>`;
- `src` и `alt` у `<img>` и `<script>`;
- `type`, `name`, `value`, `placeholder`, `required`, `disabled`, `checked` у `<input>`;
- `action`, `method` у `<form>`;
- `for` у `<label>`;
- `width`, `height` у `<canvas>` и `<img>`.

Пример из лабораторной:

```html
<input id="xInput" class="formInput" type="text" name="x"
       maxlength="12" autocomplete="off" placeholder="−5...3">
```

## 3. Структура HTML-страницы. Объектная модель документа (DOM)

### Структура страницы

1. **`<!DOCTYPE html>`** — объявление типа документа (версии HTML). В HTML5 оно такое короткое. В HTML 4.01 было длинным:
   `<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" "http://www.w3.org/TR/html4/strict.dtd">`.
   Без DOCTYPE браузер включает «режим совместимости» (quirks mode) и может отображать страницу иначе.
2. **`<html>`** — корневой элемент; атрибут `lang` задаёт язык.
3. **`<head>`** — служебная информация, не отображается на странице: кодировка, заголовок вкладки, подключение стилей и скриптов, мета-теги.
4. **`<body>`** — всё видимое содержимое.

```html
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Лабораторная работа №1</title>
    <link rel="stylesheet" href="style.css">
</head>
<body>
    <header class="header">Шапка</header>

    <main class="main">
        <section>Основное содержимое</section>
    </main>

    <footer class="footer">Подвал</footer>

    <!-- скрипт в конце body: к моменту его запуска все элементы уже созданы -->
    <script src="index.js"></script>
</body>
</html>
```

### DOM (Document Object Model)

**DOM** — платформо- и языково-независимый интерфейс (стандарт **W3C/WHATWG**), который позволяет программам и скриптам получать доступ к содержимому HTML-документа и **изменять его структуру, содержимое и стили**.

- Браузер разбирает HTML и строит из него **дерево узлов**.
- Узлы связаны отношением **«родитель — потомок»** (а также «соседи»/sibling).
- Корень дерева — объект `document`.
- Используется для **динамического изменения** страницы (DHTML).

Виды узлов: **документ** (`document`), **элементы** (`<p>`, `<div>`), **текстовые узлы**, **комментарии**. Атрибуты в современном DOM — свойства элементов, а не узлы дерева.

Пример дерева:

```html
<body>
  <h1>Заголовок</h1>
  <p>Текст <b>жирный</b></p>
</body>
```

```
document
└── html
    ├── head
    └── body
        ├── h1
        │   └── #text "Заголовок"
        └── p
            ├── #text "Текст "
            └── b
                └── #text "жирный"
```

### Работа с DOM из JavaScript

```js
// Поиск элементов
const form   = document.getElementById('pointForm');
const inputs = document.querySelectorAll('.formInput');   // по CSS-селектору
const radio  = document.querySelector('input[name="y"]:checked');

// Изменение содержимого и атрибутов
const title = document.querySelector('h1');
title.textContent = 'Новый заголовок';
title.setAttribute('title', 'подсказка');

// Работа с классами и стилями
title.classList.add('active');
title.classList.toggle('hidden');
title.style.color = 'red';

// Создание и добавление узлов
const row = document.createElement('tr');
const cell = document.createElement('td');
cell.textContent = '1.5';
row.append(cell);
document.getElementById('resultsBody').prepend(row);

// Удаление узла
row.remove();

// Навигация по дереву
cell.parentElement;      // <tr>
row.children;            // коллекция дочерних элементов
cell.nextElementSibling; // следующий сосед

// События
form.addEventListener('submit', (event) => {
    event.preventDefault();   // отменить перезагрузку страницы
});
```

**BOM (Browser Object Model)** не следует путать с DOM. Это объекты браузера, а не документа: `window`, `location`, `history`, `navigator`, `screen`, `localStorage`, таймеры `setTimeout`.

## 4. HTML-формы

**Форма** нужна для обмена данными между пользователем и сервером: пользователь заполняет поля, данные отправляются HTTP-запросом.

### Правила размещения форм

- Границы формы задаются тегами `<form>...</form>`.
- На странице может быть **любое число форм**, но **одновременно** на сервер отправляется **только одна**.
- **Вложенные формы запрещены.**
- Внутри формы можно использовать обычную разметку (`div`, `p`, `fieldset`) для группировки полей.
- Каждому полю, которое нужно отправить, обязательно задаётся атрибут **`name`**: в запрос попадают пары `name=value`.
- Поле можно связать с формой и вне её через атрибут `form="idФормы"`.

### Задание метода HTTP-запроса

Метод задаётся атрибутом **`method`** у `<form>`, а адрес обработчика — атрибутом **`action`**:

```html
<form method="GET" action="/check">...</form>    <!-- /check?x=1&y=2&r=3 -->
<form method="POST" action="/check">...</form>   <!-- данные в теле запроса -->
```

- `method="get"` — это значение по умолчанию: данные добавляются к URL.
- `method="post"` — данные передаются в теле запроса.
- HTML-форма умеет отправлять только `GET` и `POST`. Другие методы (`PUT`, `DELETE`) отправляются из JavaScript через `fetch` или `XMLHttpRequest`.
- `enctype` задаёт кодировку тела:
  - `application/x-www-form-urlencoded` — по умолчанию;
  - `multipart/form-data` — **обязательно для загрузки файлов**;
  - `text/plain`.

Если `action` не указан, форма отправляется на текущий адрес. В лабораторной форма вообще не отправляется на сервер: обработчик `submit` вызывает `event.preventDefault()`, а проверка выполняется в JavaScript.

### Виды полей ввода

| Элемент | Назначение |
|---|---|
| `<input type="text">` | Однострочный текст (в лабораторной — X и R) |
| `<input type="password">` | Пароль (символы скрыты) |
| `<input type="email">`, `tel`, `url` | Email / телефон / адрес с подходящей клавиатурой и проверкой |
| `<input type="number">`, `range` | Число / ползунок (`min`, `max`, `step`) |
| `<input type="date">`, `time`, `datetime-local`, `color` | Выбор даты, времени, цвета |
| `<input type="checkbox">` | Флажок (можно выбрать несколько) |
| `<input type="radio">` | Переключатель: **один** вариант из группы с одинаковым `name` (в лабораторной — Y) |
| `<input type="file">` | Выбор файла |
| `<input type="hidden">` | Скрытое значение |
| `<input type="submit">`, `reset`, `button` | Кнопки |
| `<textarea>` | Многострочный текст |
| `<select>` + `<option>` | Выпадающий список (`multiple` — множественный выбор) |
| `<button>` | Кнопка (`type="submit"` по умолчанию, `reset`, `button`) |
| `<label>` | Подпись к полю (`for="id"`), клик по ней активирует поле |
| `<fieldset>` + `<legend>` | Группа полей с заголовком |

Атрибуты для встроенной проверки: `required`, `min`, `max`, `minlength`, `maxlength`, `pattern`, `step`. Атрибут `novalidate` у формы отключает встроенную проверку браузера (как в лабораторной, где проверка своя на JS).

Пример:

```html
<form method="POST" action="handler.php">
    <fieldset>
        <legend>Анкета</legend>

        <label for="name">Имя:</label>
        <input id="name" type="text" name="name" required>

        <p>Что означает «ОС»?</p>
        <label><input type="radio" name="answer" value="a1"> Офицерский состав</label>
        <label><input type="radio" name="answer" value="a2" checked> Операционная система</label>

        <label><input type="checkbox" name="agree" value="yes"> Согласен</label>

        <select name="city">
            <option value="spb">Санкт-Петербург</option>
            <option value="msk">Москва</option>
        </select>

        <textarea name="comment" rows="3"></textarea>
    </fieldset>

    <button type="submit">Отправить</button>
</form>
```

При отправке методом `POST` тело запроса будет таким: `name=Ира&answer=a2&agree=yes&city=spb&comment=...`

## 5. Каскадные таблицы стилей (CSS)

**CSS (Cascading Style Sheets)** — язык описания **внешнего вида** документа: цветов, шрифтов, отступов, расположения блоков, анимаций.

**Основная цель** — **разделить содержимое** (HTML) **и его представление** (CSS). Это позволяет показывать один и тот же документ по-разному: на экране, на печати, на телефоне.

### Источники стилей

1. **Авторские стили** (от автора страницы):
   - **inline** — в атрибуте `style`: `<p style="color: red">`;
   - **встроенные** — в блоке `<style>` внутри HTML;
   - **внешние** — в отдельном файле `.css`, подключаемом через `<link rel="stylesheet" href="style.css">` (так требует задание лабораторной).
2. **Пользовательские стили** — CSS-файл, заданный пользователем в настройках браузера.
3. **Стили браузера** — стандартное оформление по умолчанию (например, `h1` крупный и жирный).

### Структура: правила и селекторы

Таблица стилей — набор **правил**. Правило = **селектор(ы)** + **блок объявлений** `свойство: значение;`:

```css
селектор, селектор {
    свойство: значение;
    свойство: значение;
}

div, td {
    background-color: red;
    padding: 8px;
}
```

### Виды селекторов

| Вид | Синтаксис | Что выбирает |
|---|---|---|
| Универсальный | `*` | все элементы |
| По тегу (типу) | `p` | все `<p>` |
| По классу | `.panel` | элементы с `class="panel"` |
| По id | `#xInput` | элемент с `id="xInput"` |
| По атрибуту | `input[type="radio"]`, `a[href^="https"]` | элементы с атрибутом / значением |
| Группировка | `h1, h2, h3` | все перечисленные |
| **Потомков** | `.header .headerItem` | `.headerItem` на **любой** глубине внутри `.header` |
| Дочерний | `ul > li` | только **прямые** дети |
| Соседний | `h2 + p` | `p` **сразу после** `h2` |
| Родственный | `h2 ~ p` | все `p` **после** `h2` на том же уровне |
| **Псевдоклассы** | `:hover`, `:focus`, `:checked`, `:disabled`, `:nth-child(even)`, `:not()`, `:first-child`, `:has()` | элементы в **определённом состоянии** или положении |
| **Псевдоэлементы** | `::before`, `::after`, `::placeholder`, `::first-letter`, `::first-line`, `::selection` | **часть** элемента или «виртуальный» элемент |
| Комбинированный | `.formInput.formInputInvalid` | элемент с **обоими** классами |

Примеры из лабораторной:

```css
/* селектор потомков */
.header .headerItem { margin-left: 24px; }

/* псевдоклассы */
.btn:hover { background-color: #143a2a; }
.btn:disabled { opacity: 0.4; }
.results tbody tr:nth-child(even) { background-color: #152011; }

/* псевдоэлемент */
.formInput::placeholder { color: #6c7a8a; }

/* два класса сразу */
.formInput.formInputInvalid { border-color: #ff5c5c; }
```

### Наследование

Часть свойств **автоматически передаётся потомкам**: в основном текстовые (`color`, `font-family`, `font-size`, `line-height`, `text-align`, `visibility`). Блочные свойства (`margin`, `padding`, `border`, `background`, `width`) **не наследуются**. Унаследовать их явно можно значением `inherit`.

```css
body { font-family: "JetBrains Mono", monospace; color: #e3e8ef; }
/* все элементы внутри body получат этот шрифт и цвет */

.formInput {
    font: inherit;    /* явно наследуем шрифт родителя (у input он по умолчанию свой) */
    color: inherit;
}
```

### Каскадирование и приоритеты правил

**Каскад** — механизм, определяющий, какое значение свойства применится, если к элементу подходят несколько правил.

Порядок приоритетов (от большего к меньшему, по лекции):

1. объявление с **`!important`**;
2. **inline-стиль** в атрибуте `style`;
3. число **id** (`#id`) в селекторе;
4. число **классов, атрибутов и псевдоклассов** (`.class`, `[type]`, `:hover`) в селекторе;
5. число **тегов и псевдоэлементов** в селекторе.

При **равной специфичности побеждает правило, написанное позже**.

Специфичность удобно записывать как `(id, классы, теги)`:

| Селектор | Специфичность |
|---|---|
| `p` | (0, 0, 1) |
| `.formInput` | (0, 1, 0) |
| `.formInput.formInputInvalid` | (0, 2, 0) |
| `.header .headerItem` | (0, 2, 0) |
| `#xInput` | (1, 0, 0) |
| `#news p` | (1, 0, 1) |
| `style="..."` | выше любого селектора |

Пример из лабораторной:

```css
.formInput       { border: 2px solid #33414f; }   /* (0,1,0) */
.formInput:focus { border-color: #3ecf8e; }        /* (0,2,0) — перекрывает при фокусе */
.formInput.formInputInvalid { border-color: #ff5c5c; } /* (0,2,0), записано позже — побеждает */
```

Ещё пример каскада: у `.header` шрифт `serif` перекрывает моноширинный шрифт, унаследованный от `body`. Собственное правило элемента всегда сильнее унаследованного значения.

### Преимущества CSS перед заданием стилей атрибутами тегов

Раньше внешний вид задавали прямо в разметке: `<font color="red">`, `<body bgcolor="...">`, `<table border="1">`, а позже через `style="..."`. Преимущества CSS:

1. **Разделение содержимого и оформления.** HTML описывает смысл, CSS — вид. Код чище и понятнее.
2. **Повторное использование.** Одно правило применяется к любому числу элементов и страниц. Чтобы поменять цвет на всём сайте, достаточно одной строки.
3. **Меньше объём страниц** и **кэширование**: внешний `.css` загружается один раз и берётся из кэша.
4. **Больше возможностей**, чем у атрибутов: отступы, позиционирование, flex/grid, анимации, псевдоклассы (`:hover`), псевдоэлементы.
5. **Разные стили для разных устройств** через медиазапросы: `@media (max-width: 900px) {...}`, `@media print {...}`.
6. **Доступность и SEO.** Чистая семантическая разметка лучше читается скринридерами и поисковиками.
7. Атрибуты оформления (`bgcolor`, `<font>`, `align`) в HTML5 **устарели**.

## 6. LESS, Sass, SCSS

**LESS, Sass и SCSS — CSS-препроцессоры**: языки стилей, которые повышают уровень абстракции CSS-кода и упрощают структуру таблиц стилей. Код на них **компилируется в обычный CSS**.

### Ключевые особенности (по сравнению с обычным CSS)

- **Переменные** (константы).
- **Вложенные правила.**
- **Примеси (mixins)** — переиспользуемые блоки объявлений с параметрами.
- **Наследование** правил (`@extend`).
- **Импорт** и разбиение на модули.
- **Математические операции** и функции (`lighten()`, `darken()` для цветов).
- Условия и циклы (`@if`, `@for`, `@each` в Sass).

### Синтаксис

| | LESS | Sass | SCSS |
|---|---|---|---|
| Синтаксис | CSS-подобный (`{}` и `;`) | отступы вместо `{}` и `;` (похож на Ruby/Python) | CSS-подобный — диалект Sass |
| Расширение | `.less` | `.sass` | `.scss` |
| Переменные | `@color` | `$color` | `$color` |
| Примеси | `.mixin();` | `=mixin` / `+mixin` | `@mixin` / `@include` |
| Компилятор | `lessc` (JavaScript, Node.js) | Dart Sass (раньше — Ruby) | тот же, что у Sass |
| Обычный CSS — валидный код? | да | нет | **да** |

Одно и то же на трёх языках:

```less
// LESS
@primary: #3ecf8e;

.btn {
    color: @primary;
    &:hover { color: darken(@primary, 10%); }
}
```

```sass
// Sass (отступы, без скобок и точек с запятой)
$primary: #3ecf8e

.btn
  color: $primary
  &:hover
    color: darken($primary, 10%)
```

```scss
// SCSS
$primary: #3ecf8e;

.btn {
    color: $primary;
    &:hover { color: darken($primary, 10%); }
}
```

### Примеры возможностей (SCSS)

**Переменные:**

```scss
$font-size-h1: 24px;
$font-size-h2: 20px;

h1 { font-size: $font-size-h1; }
h2 { font-size: $font-size-h2; }
```

**Вложенность** (`&` — ссылка на родительский селектор):

```scss
#header {
    background: #fff;
    .error { color: #f00; }
    a {
        text-decoration: none;
        &:hover { text-decoration: underline; }
    }
}
```

компилируется в:

```css
#header { background: #fff; }
#header .error { color: #f00; }
#header a { text-decoration: none; }
#header a:hover { text-decoration: underline; }
```

**Примеси:**

```scss
@mixin border-radius($radius, $border, $color) {
    -webkit-border-radius: $radius;
    border-radius: $radius;
    border: $border solid $color;
}

.box { @include border-radius(10px, 1px, red); }
```

```css
.box {
    -webkit-border-radius: 10px;
    border-radius: 10px;
    border: 1px solid red;
}
```

**Наследование:**

```scss
.message { border: 1px solid #ccc; padding: 10px; color: #333; }
.success { @extend .message; border-color: green; }
.error   { @extend .message; border-color: red; }
```

**Импорт** (файлы с `_` в начале — partials, сами в CSS не компилируются):

```scss
// base.scss
@import 'reset';   // подключит _reset.scss (в новом Sass — @use)
body { font: 100% Helvetica, sans-serif; }
```

**Математика:**

```scss
article { width: 600px / 960px * 100%; }   // 62.5%
```

### Совместимость с браузерами и трансляция в обычный CSS

- **Браузеры не понимают LESS/Sass/SCSS напрямую.** Нужен **транслятор (компилятор)**, который превращает их в обычный CSS. На страницу всегда подключается **итоговый `.css`**.
- Поэтому совместимость итогового кода определяется **только сгенерированным CSS**: если он использует поддерживаемые свойства, страница работает в любом браузере.
- Способы компиляции:
  - из командной строки:
    ```bash
    npm install -g sass less
    sass styles.scss styles.css          # Sass/SCSS
    sass --watch scss/:css/              # пересборка при изменении
    lessc styles.less styles.css         # LESS
    ```
  - в сборщиках (Webpack, Vite, Gulp), в IDE, в Maven через плагин (`sass-maven-plugin`, пример из лекции);
  - LESS можно компилировать прямо в браузере скриптом `less.js`, но так делают только для отладки: это медленно.
- Современный CSS частично перенял эти возможности: появились **переменные** (`--main-color: #3ecf8e; color: var(--main-color);`), **вложенность** (CSS Nesting) и функция `calc()`. Но препроцессоры по-прежнему дают примеси, циклы, функции и модульность.

## 7. Клиентские сценарии. JavaScript. ECMAScript, ES6 и ES7

### Клиентские сценарии

**Клиентский сценарий** — программа, которая выполняется **в браузере пользователя**, а не на сервере.

Особенности:

- выполняется на компьютере клиента, без обращения к серверу, поэтому реакция быстрая и сервер разгружен;
- имеет доступ к странице через **DOM** и к браузеру через **BOM**;
- работает в **«песочнице»**: нет прямого доступа к файлам компьютера, запросы к другим сайтам ограничены политикой одного источника (same-origin policy);
- **код открыт** — его видит любой пользователь;
- **нельзя полагаться на клиентскую проверку** как на защиту: пользователь может её отключить или отправить запрос в обход, поэтому сервер должен проверять данные повторно;
- может быть отключён в браузере.

Сферы применения:

- **проверка (валидация) данных форм** до отправки (как X и R в лабораторной);
- реакция на действия пользователя: клики, ввод, наведение;
- динамическое изменение страницы без перезагрузки (**DHTML**): показ/скрытие блоков, добавление строк в таблицу;
- обмен данными с сервером в фоне (**AJAX**: `XMLHttpRequest`, `fetch`; WebSocket);
- графика и анимация (`<canvas>`, SVG, WebGL) — в лабораторной на Canvas нарисована область;
- хранение данных на клиенте: cookies, **LocalStorage** (в лабораторной так хранится таблица результатов), IndexedDB;
- одностраничные приложения (SPA) на фреймворках: React, Angular, Vue.

### Язык JavaScript

**JavaScript** — объектно-ориентированный скриптовый язык, используемый прежде всего для интерактивности веб-страниц. Сейчас он работает и на сервере (Node.js).

Основные черты:

- **динамическая типизация:** тип принадлежит значению, а не переменной;
- **слабая типизация:** неявные преобразования типов, например `'5' * 2 === 10`, `'5' + 2 === '52'`;
- **автоматическое управление памятью** (сборщик мусора);
- **прототипное наследование:** объекты наследуют от других объектов через `prototype`;
- **функции — объекты первого класса:** их можно присваивать переменным, передавать и возвращать;
- однопоточность с **событийным циклом** (event loop) и асинхронностью: колбэки, промисы, `async/await`.

Особенности синтаксиса:

- идентификаторы **регистрозависимы** (`xInput` ≠ `xinput`);
- в именах можно использовать буквы, цифры, `_` и `$`, но **нельзя начинать с цифры**;
- комментарии: `// однострочный` и `/* многострочный */`.

Структура JS в браузере:

1. **Ядро (ECMAScript)** — сам язык: типы, операторы, функции, объекты.
2. **BOM** (Browser Object Model) — объекты браузера: `window`, `location`, `history`, `navigator`, таймеры, cookies.
3. **DOM** — доступ к документу.

**Типы данных:**

- примитивы: `number`, `string`, `boolean`, `null`, `undefined`, а с ES6 и позже — `symbol`, `bigint`;
- объектный тип: `object` (сюда относятся массивы и функции).

**Способы подключения к странице:**

```html
<!-- 1. В отдельном файле (лучший вариант, как в лабораторной) -->
<script src="index.js"></script>

<!-- 2. Внутри страницы -->
<script>
    console.log('Hello, World!');
</script>

<!-- 3. В атрибуте-обработчике (устаревший стиль, смешивает разметку и код) -->
<a href="delete.php" onclick="return confirm('Вы уверены?');">Удалить</a>
```

Отделение кода от разметки через DOM:

```js
document.getElementById('clearBtn').addEventListener('click', () => {
    results = [];
    renderTable();
});
```

### Версии ECMAScript

**ECMAScript** — стандарт языка (спецификация **ECMA-262**), а JavaScript — его реализация.

| Версия | Год | Главное |
|---|---|---|
| ES1 | 1997 | первая спецификация |
| ES2 | 1998 | редакционные правки |
| ES3 | 1999 | регулярные выражения, `try/catch` |
| ES4 | — | **не вышла** (слишком радикальные изменения) |
| ES5 | 2009 | `"use strict"`, `JSON`, `Array.prototype.forEach/map/filter/reduce`, геттеры/сеттеры |
| ES5.1 | 2011 | уточнения |
| **ES6 / ES2015** | 2015 | крупнейшее обновление (см. ниже) |
| **ES7 / ES2016** | 2016 | `Array.prototype.includes`, оператор `**` |
| ES2017 | 2017 | `async/await`, `Object.values/entries`, `padStart/padEnd` |
| ES2018 и далее | ежегодно | rest/spread для объектов, `?.`, `??`, `BigInt`, `Array.prototype.at` и др. |

С 2015 года новая версия выходит **каждый год** и называется по году: ES2016, ES2017… Старые браузеры поддерживают не все новые возможности, поэтому для них код переводят в ES5 **транспилером** (например, **Babel**).

### Новые возможности ES6 (ES2015)

**1. `let` и `const` — блочная область видимости.** `var` виден во всей функции, а `let` и `const` — только внутри блока `{}`:

```js
function test(inner) {
    var a = 'outer';
    let b = 'outer';
    if (inner) {
        var a = 'inner';   // перезаписывает внешнюю a
        let b = 'inner';   // новая переменная только в этом блоке
    }
    return [a, b];
}
test(true); // ['inner', 'outer']

const MAX = 7;
MAX = 20;  // TypeError: константу нельзя переприсвоить
```

**2. Шаблонные строки:**

```js
const name = 'Ира';
console.log(`Привет, ${name}! Сейчас ${new Date().getHours()} часов`);
```

**3. Стрелочные функции.** Короткая запись и **нет своего `this`**, он берётся из внешнего контекста:

```js
const square = x => x * x;
const ids = [291, 288];
const messages = ids.map(id => `ID is ${id}`);
button.addEventListener('click', () => this.sendData());
```

**4. Деструктуризация:**

```js
const [first, , third] = [1, 2, 3];          // 1 3
let a = 1, b = 2;
[a, b] = [b, a];                             // обмен значений

const { x, y, r } = { x: 1, y: 2, r: 3 };
function getFullName({ firstName, lastName }) {
    return `${firstName} ${lastName}`;
}
```

**5. Параметры по умолчанию, rest и spread:**

```js
function point(x = 0, y = -1) { return [x, y]; }
point();        // [0, -1]

function sum(...nums) { return nums.reduce((s, n) => s + n, 0); }  // rest
sum(1, 2, 3);   // 6

Math.max(...[2, 100, 1]);         // spread → 100
const all = [...arr1, ...arr2];   // объединение массивов
```

**6. Классы и наследование** (удобная запись над прототипами):

```js
class Animal {
    constructor(name) { this.name = name; }
    speak() { console.log(`${this.name} makes a noise.`); }
}

class Lion extends Animal {
    speak() {
        super.speak();
        console.log(`${this.name} roars.`);
    }
}

new Lion('Simba').speak();
// Simba makes a noise.
// Simba roars.
```

**7. Промисы** вместо вложенных колбэков:

```js
function wait(ms) {
    return new Promise(resolve => setTimeout(resolve, ms));
}

wait(1000)
    .then(() => console.log('прошла секунда'))
    .catch(err => console.error(err));
```

**8. Цикл `for...of` и итераторы:**

```js
for (const item of ['a', 'b', 'c']) {
    console.log(item);
}
```

**9. Модули:**

```js
// math.js
export function sum(a, b) { return a + b; }
export default class Calculator {}

// main.js
import Calculator, { sum } from './math.js';
```

**10. Другое:** сокращённая запись свойств объекта (`{ x, y }` вместо `{ x: x, y: y }`), новые структуры данных `Map`, `Set`, `WeakMap`, `WeakSet`, тип `Symbol`, генераторы `function*`, `Array.from`, `Object.assign`, `String.prototype.includes/startsWith`.

### Новые возможности ES7 (ES2016)

ES7 — небольшое обновление, в нём всего **две** новые возможности.

**1. `Array.prototype.includes`** — проверить, есть ли элемент в массиве. В отличие от `indexOf`, умеет находить `NaN` и сразу возвращает `true`/`false`:

```js
const Y_VALUES = [-3, -2, -1, 0, 1, 2, 3, 4, 5];
Y_VALUES.includes(2);     // true  (используется в лабораторной при проверке Y)
Y_VALUES.includes(7);     // false

[NaN].indexOf(NaN);       // -1 — ошибка старого способа
[NaN].includes(NaN);      // true
```

**2. Оператор возведения в степень `**`:**

```js
2 ** 10;            // 1024 (раньше: Math.pow(2, 10))
let n = 3;
n **= 2;            // 9
```
