# Карточки по архитектуре компьютера

Тренажёр экзаменационных билетов: **234 вопроса** курса «Архитектура компьютера» (2026.1 + 2026.2)
с развёрнутыми ответами, составленными по конспектам лекций. Одна сторона карточки — вопрос,
другая — ответ на 4–7 тезисов, рассчитанный на устный ответ за полминуты-минуту.

Приложение — обычная веб-страница без сервера, без сборщика и без зависимостей.
Прогресс («знаю» / «не знаю») хранится в браузере.

---

## Быстрый старт

**Вариант 1. Просто открыть файл.** Откройте `dist/index.html` двойным кликом.
Работает офлайн, ничего устанавливать не нужно. Этот файл можно скинуть себе в мессенджер,
на флешку или в облако — он самодостаточен (внутри и стили, и логика, и все карточки).

**Вариант 2. Локальный сервер** (нужен, если хотите PWA-установку или правите исходники):

```bash
npm run start        # соберёт dist/ и поднимет http://localhost:8080
```

**Вариант 3. Выложить в интернет.** Содержимое `dist/` — статический сайт.
Подходит любой бесплатный хостинг: GitHub Pages, Netlify, Vercel, Cloudflare Pages.

```bash
npm run build                     # собрать dist/
# GitHub Pages: залить репозиторий, в Settings → Pages выбрать ветку и папку /dist
```

С хостинга страницу можно **установить на телефон** (Chrome → «Добавить на главный экран»):
есть манифест и service worker, после установки работает офлайн.

## Управление

| Действие | Клавиша | Мышь / телефон |
|---|---|---|
| Перевернуть карточку | `Пробел` | клик по карточке |
| Следующая / предыдущая | `→` / `←` | кнопки, свайп |
| Отметить «знаю» / снять отметку | `Enter` | кнопка «✓ Знаю» |
| Перемешать колоду | `S` | переключатель «Перемешать» |
| Случайная карточка | `R` | — |

Фильтр по разделу и режим «только невыученные» сужают колоду.
Полоса-шина под панелью — все карточки колоды: бирюзовые отмечены как выученные,
оранжевая — текущая; по любому делению можно кликнуть и перейти к карточке.

```
│   ├── app.js                логика: колода, фильтры, переворот, прогресс в localStorage

│   └── icon.svg              иконка
├── scripts/
│   ├── build.mjs             src + data → dist/
│   └── export.mjs            data → export/ (Anki, Quizlet, CSV, Markdown, печать)
├── dist/                     собранный сайт (index.html — автономный файл)
├── export/                   выгрузки в другие форматы
└── package.json              команды build / export / start, зависимостей нет
```

### Формат карточки

```json
{
  "id": 1,
  "topic": "Введение",
  "question": "Что такое «вычислительная платформа» с точки зрения пользователя?",
  "answer": [
    "Первый абзац — суть ответа одним предложением.",
    "Дальше — тезисы, каждый выводится отдельным пунктом.",
    "Порядок пунктов = порядок устного ответа."
  ]
}
```

`id` совпадает с номером вопроса в исходном списке билетов, `topic` формирует фильтр разделов.
Чтобы добавить или поправить вопрос — правьте `data/cards.json` и выполните `npm run build`.

## Другие форматы (`npm run export`)

| Файл | Куда |
|---|---|
| `export/anki.tsv` | импорт в **Anki**: «Файл → Импорт», разделитель — табуляция, поля «Вопрос / Ответ / Теги», HTML включён. Даёт интервальные повторения и синхронизацию с телефоном. |
| `export/quizlet.txt` | вставка в **Quizlet**: «Импортировать», разделитель между термином и определением — табуляция, между карточками — пустая строка. |
| `export/cards.csv` | Excel, Google Sheets, любая своя обработка. |
| `export/cards.md` | конспект-шпаргалка по разделам с оглавлением — для чтения и печати. |
| `export/print.html` | вёрстка под печать: откройте и Ctrl+P → «Сохранить как PDF». |

## Куда развивать

Ниже — варианты структуры, каждый решает свою задачу. Первые два — самые дешёвые.

1. **Интервальные повторения вместо бинарного «знаю».** Сейчас карточка помечается одной
   отметкой. Алгоритм SM-2 (как в Anki) хранил бы для каждой карточки интервал и лёгкость и
   показывал бы к повторению только то, что пора. Меняется только `app.js` и формат записи в
   localStorage. Либо просто выгружайте `export/anki.tsv` и учите в Anki.

2. **Режим экзамена.** Генератор билетов ровно как в задании (5 билетов по 2 вопроса,
   номера из общей перетасованной колоды), таймер на ответ и итоговый лист «что не вспомнил».
   Отдельная страница `exam.html`, те же данные.

3. **Синхронизация прогресса между устройствами.** Сейчас прогресс живёт в одном браузере.
   Варианты: экспорт/импорт прогресса файлом (десяток строк кода), либо бэкенд —
   Supabase/Firebase, либо хранение в артефакте Claude с общей базой на группу.

4. **Разделение колоды на модули.** Вместо одного `cards.json` — по файлу на лекцию
   (`data/01-course.json` … `data/16-duncan.json`) и сборка со склейкой. Удобнее вести правки
   вдвоём-втроём и видеть осмысленный diff в git.

5. **Совместное ведение.** Репозиторий на GitHub + Pages: одногруппники присылают
   pull request с исправлением ответа, страница пересобирается автоматически (GitHub Action на
   `npm run build`). Колода становится общим конспектом потока.

6. **Схемы и формулы в ответах.** Часть вопросов (конвейер, кеш, MOESI, классификация Дункана)
   легче вспоминать по картинке. Ответ можно расширить полем `svg` или `mermaid` и рисовать
   схему на обороте; формулы — через KaTeX.

7. **Проверка формулировкой.** Режим, где ответ вводится текстом, а сравнение — по ключевым
   терминам карточки (список `keywords`). Даёт активное вспоминание вместо узнавания.

8. **Телеграм-бот.** Те же `cards.json`, бот присылает вопрос, по кнопке — ответ, ведёт статистику.
   Полезно, если учить в транспорте.

## Лицензия и оговорка

Код — свободно используйте. Тексты ответов составлены по конспектам лекций курса
и предназначены для подготовки к экзамену; проверяйте спорные места по первоисточнику —
формулировки преподавателя всегда главнее.
